04 Protocolo IPFS vs Gateway HTTP

🌐 Protocolo IPFS

Red peer-to-peer donde los nodos se identifican por contenido (CID = hash del contenido). El acceso nativo requiere un cliente como Kubo o Brave. Es descentralizado por diseño: el contenido vive en cualquier nodo que lo tenga.

🔗 Gateway HTTP

Servidor centralizado que actúa como puente entre HTTP e IPFS. Permite resolver https://gateway/ipfs/<CID> sin cliente IPFS. Conveniente, pero introduce un punto centralizado de fallo: si el gateway cae, la URL falla aunque el contenido siga en la red.

05 Disponibilidad vs Política de eliminación

📡 Availability

Mientras el pin esté activo en Pinata, al menos un nodo almacena y sirve el CID. Cualquier gateway público puede resolverlo siempre que exista al menos un nodo con el contenido.

🗑️ Unpin & Deletion

IPFS no garantiza borrado por diseño. Si unpinneamos, Pinata dejará de servir el CID, pero otros nodos o gateways que lo hayan cacheado podrían seguir sirviéndolo por tiempo indeterminado. Si unpinneamos, esperamos que el CID deje de resolverse desde el gateway de Pinata en horas o días, sin poder garantizar su desaparición total de la red.

06 Compromisos de PactTrail
✗ PactTrail NO hará
🚫 Subir PII, KYC ni datos de identidad de las partes a IPFS público. Nombres, correos, documentos y wallets vinculadas a personas nunca irán a una red inmutable.
🚫 Commitear JWT, API keys ni claves privadas en ningún repositorio. Ningún secreto aparecerá en el historial de Git, CI/CD ni logs públicos.
🚫 Ofrecer garantía de borrado de contenido pinneado en IPFS. El retiro de pin es best-effort, no un borrado garantizado del protocolo.
✓ PactTrail SÍ hará
✅ Mantener un pin activo y verificable para cualquier artefacto de referencia técnica anunciado públicamente (código de contrato, ABI, documentación de versiones), permitiendo que los usuarios verifiquen la integridad del contenido mediante su CID sin depender de un servidor centralizado.
07 Nota: Arweave (contraste — no utilizado en este lab)
Arweave es una red de almacenamiento permanente con modelo de pago único (endowment): al subir un archivo se paga una tarifa que financia su almacenamiento indefinido. A diferencia de IPFS con pinning activo, no requiere renovación de pin. Para PactTrail podría ser relevante para versiones auditadas de contratos que se quieran preservar sin mantenimiento operativo. No se utilizó Arweave en este lab: el objetivo es demostrar el ciclo IPFS + pin; Arweave aparece aquí solo como nota de contraste (pay-once / endowment).
